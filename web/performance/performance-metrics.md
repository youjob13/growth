## Critical Performance Metrics

Разработчик должен полагаться на UPP (User-perceived performance) - зависит от - CRR (Critical Rendering Path)

- First paint - момент, когда приложение загрузило достаточно данных и ресурсов, чтобы отрисовать первый - начальный - кадр
- Time to interactive - момент, когда пользователю становится доступна возможность нажать кнопку, а приложение может ему ответить
- Full Load - момент, когда весь пользовательские интерфейс отрисован и доступен для пользователя

## Тайминги производительности
Нет конкретных значений, определяющих медленную скорость загрузки страницы, но есть рекомендации:

 | Загрузка контента | Ожидание | Анимация | Ответ на действие пользователя |
 |-------------------|----------|----------|--------------------------------|
 | 1с | 50мс | 16.7мс | от 50 до 200мс |

## How to optimize First Paint

- Улучшать CRR - выполнять при запуске приложения только тот код, который необходим
- Кешировать ресурсы локально

## Частота кадров (FPS)

Важнейшая вещи для высокой частоты кадров - использование правильных инструментов: 
- HTML и CSS для создания статического контента
- Canvas для создания высокодинамического контента (полный контроль над всем, что отрисовывается / частотой кадров)
- Использовать CSS-анимации (e.g. [CSS Transitions](https://developer.mozilla.org/ru/docs/Web/CSS/Guides/Transitions/Using)), transform - для изменения позиции, масштаба  - часть вычислений переносится на GPU
- Использовать RAF (Request Animation Frame) вместо setInterval / setTimeout

## Способы оптимизации
- Выносить код в web-workers
- Разбивать всё что должно быть выполнено в основном потоке на мелкие куски кода
- Lazy loading стратегии:
  - Общий подход - code splitting JavaScript, CSS и HTML могут быть разделены на небольшие chunks. При first page load отправлять только необходимые части. Есть 2 вида code splitting: entrypoint и dynamic.import()
  - JavaScript - указание type="module" автоматически рассматривается как JavaScript module, а его загрузка откладывается по умолчанию
  - CSS - по умолчанию CSS считается ресурсом блокирующим рендеринг. Браузер не будет отображать контент до тех пор, пока не будет построена CSSOM
  - Fonts - по умолчанию, загрузка шрифтов откладывается на тот момент, пока Render Tree не сформировано полностью. Это приводит к тому, что текст страницы может появиться не сразу. Можно переопределить используя **rel="preload"**
  - Images - **loading** атрибут элемента img может быть использован, чтобы указать браузеру на необходимость отложить загрузку изображения / iframe до тех пор, пока пользователь не доскроллит до них
- Speculative loading:
  - Prefetching - включает предзагрузку некоторых или всех ресурсов требуемых для отрисовки документа, до того как они будут нужны. Так что как время для их рендеринга настанет, рендеринг может произойти намного быстрее
  - Prerendering - отрисовывает контет готовый для отображения когда потребуется. Может быть результатом мгновенной навигации из старых страниц в новые
  - Preconnecting - включает ускорение будущих загрузок для указанных доменов (отличающихся от основного домена сайта), выполняя частичную предзагрузку (DNS resolution + TCP handshake + TLS negotiation)

  | Механизм | Что делает | Когда срабатывает | Приоритет | Влияние на текущую страницу |
  |----------|------------|-------------------|-----------|-----------------------------|
  | `dns-prefetch` | Только DNS-резолвинг домена | Сразу | Очень низкий | Практически нет |
  | `preconnect` | DNS + TCP + TLS | Сразу | Высокий | Небольшая нагрузка на сеть |
  | `preload` | Скачивает ресурс в кэш | Сразу, как увидит тэг | Высокий | Ресурс занимает память, может конкурировать с критическими ресурсами |
  | `modulepreload` | Скачивает и парсит JS-модуль | Сразу | Высокий | То же, что и preload + парсинг модуля |
  | `prefetch` | Скачивает ресурс в HTTP-кэш | В простое, после основной загрузки | Низкий | Минимальное |
  | `prerender` | Скачивает и рендерит страницу целиком | В фоне | Низкий | Большой расход ресурсов |
  | Speculation Rules API | Современная замена `prerender` и `prefetch` | Настраивается | Настраивается | Контролируемый расход |
