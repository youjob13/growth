## Critical Performance Metrics

Разработчик должен полагаться на UPP (User-perceived performance) - зависит от - CRR (Critical Rendering Path)

- First paint - момент, когда приложение загрузило достаточно данных и ресурсов, чтобы отрисовать первый - начальный - кадр
- Time to interactive - момент, когда пользователю становится доступна возможность нажать кнопку, а приложение может ему ответить
- Full Load - момент, когда весь пользовательские интерфейс отрисован и доступен для пользователя

## Тайминги производительности
Нет конкретных значений, определяющих медленную скорость загрузки страницы, но есть рекомендации:

 | Загрузка контента | Ожидание | Анимация | Ответ на действие пользователя |
 |-------------------|----------|----------|--------------------------------|
 | 1с | 50мс | 16.7мс | от 50 до 200мс |

## How to optimize First Paint

- Улучшать CRR - выполнять при запуске приложения только тот код, который необходим
- Кешировать ресурсы локально

## Частота кадров (FPS)

Важнейшая вещи для высокой частоты кадров - использование правильных инструментов: 
- HTML и CSS для создания статического контента
- Canvas для создания высокодинамического контента (полный контроль над всем, что отрисовывается / частотой кадров)
- Использовать CSS-анимации (e.g. [CSS Transitions](https://developer.mozilla.org/ru/docs/Web/CSS/Guides/Transitions/Using)), transform - для изменения позиции, масштаба  - часть вычислений переносится на GPU
- Использовать RAF (Request Animation Frame) вместо setInterval / setTimeout
